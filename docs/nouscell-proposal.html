NOUSCELLνοῦς + cell · a sealed cell of intelligence · NOWSS-cell

Intelligence runs in a sealed cell, does the work, and dissolves — leaving nothing behind. The distro moves to the host. The cell owns nothing. Every tool is attested memory, lent in and revocable in microseconds.

A walkthrough of the design: why the current sandbox stack stops one layer too early, what a guest built from first principles looks like, and what becomes possible when software is a service the host provides to the process rather than property the machine owns.

0x00The problem

Agents got sandboxes. They never got an operating system.

The industry solved the perimeter and declared victory. Inside the wall, the agent still lives in a 1990s workstation.

The last two years converged fast. Isolation settled on hardware-virtualised microVMs — every major provider reached for its strongest primitive, and none of them reached for containers. Boot latency collapsed: copy-on-write forks of warm VM snapshots now spawn a fully isolated KVM machine in under a millisecond, at a few hundred kilobytes of real memory. Policy hardened at the edge: default-deny egress, credential injection at the boundary so secrets never enter the guest at all.

~0.8ms
to fork a hardware-isolated VM from a warm snapshot — boot is a solved problem
~40s
for the agent to then run npm install inside it — the cost moved, it didn't vanish

But open the microVM and look inside. It's Debian. A full TCP/IP stack the host proxy immediately firewalls off. systemd, udev, a dynamic linker, a package manager pulling from the public internet, hundreds of setuid-era userland packages, error messages written for humans with terminals. Every layer of it is attack surface the perimeter has to compensate for, latency the snapshot has to carry, and ambiguity the agent has to burn tokens interpreting.

The gap in the field

Ninety percent of agent-infrastructure engineering is host-side: hypervisors, proxies, policy engines. Almost nobody is building the guest — the cell itself. That's the leanest available target, and the layer where security, speed, and density stop being tradeoffs and become the same cut.

Three specific failures follow from running a human OS under a machine tenant:

1 · The supply chain runs through every sandbox. Each guest independently resolves, downloads, and executes packages from public registries. Ten thousand sandboxes means ten thousand copies of the attack surface, verified zero times.

2 · The environment is the latency. Sub-millisecond fork is meaningless when materialising the toolchain takes tens of seconds. Dependency graphs, not boot, are where wall-clock time goes.

3 · The OS speaks the wrong language. EACCES, pagers, spinners, ANSI codes, non-deterministic output. Every human-oriented ambiguity costs the agent tokens and turns — and failed turns are the most expensive resource in the loop.

0x01The inversion

Move the distro to the host. Lend the tools to the cell.

Stop treating tools as software installed in the OS. Treat them as memory the host lends to the process.

In Nouscell, the cell owns nothing. No packages, no network stack, no credentials, no update mechanism. Python, git, compilers, curl — everything the agent thinks of as "the OS" — is attested memory mapped in by the host on demand, shared across every sandbox on the machine, and revocable instantly. The agent experiences a normal Linux box. What actually exists is a lease.

The nearest historical analogy is the diskless workstation of the NFS era — with the trust model inverted. Instead of mounting files from a server you trust, the cell executes pages from a host that attests, while the tenant — the workload, plus whatever it downloaded — is presumed hostile.

This single move is what buys all three axes at once, because they stop being separate problems:

AxisWhat the inversion does
SmallThe cell carries no payload. Per-sandbox cost collapses to dirty pages plus one tmpfs workspace.
FastProvisioning becomes page-table operations on warm copy-on-write snapshots — not downloads, not installs.
SecureThe supply chain narrows to one hardened host pipeline. The cell is structurally unable to execute anything that didn't come through it.
The one-line version

A computer where software is a service the host provides to the process, not property the machine owns — and Linux compatibility is maintained purely as an illusion for the agent's benefit, because that is what the models were trained on.

0x02The cell

A kernel of ~70 syscalls. A userland of one binary.

Because the cell never boots in production — it forks from a snapshot — stripping the kernel isn't about boot speed. The substrate at rest is a mote: the ~70-syscall kernel plus pilot, a bootable-but-almost-empty Linux image. A cell is a mote that's been forked, sealed, and had tools loaned in. Stripping the mote is about attack surface (every subsystem compiled out is a CVE class that cannot exist), fork density (fewer kernel structures touched per task means fewer dirty pages, means more cells per host), and determinism (reproducible motes that dedupe).

Kept — load-bearing

Memory management and copy-on-write (this is the loading mechanism) · scheduler, threads, futex · VFS with tmpfs and one read-only content-addressed mount · epoll, pipes, vsock · Landlock + seccomp as the in-cell enforcement ring.

Cut — and why it's safe

Block layer, filesystems with journaling, kernel modules, io_uring, userfaultfd, eBPF, perf, ptrace, ACPI, swap, USB/sound/graphics, SysV IPC, most of PCI — and the entire in-kernel network stack.

The highest-leverage cut

Networking is not deleted as an ABI — it's deleted as an implementation. AF_INET still exists to the application; a thin shim marshals it over vsock to the host proxy, which owns DNS, TLS, egress policy, and credential injection. Zero network code in the kernel. Full binary compatibility for pip, git, and curl.

Userland: dump the plumbing, keep the contract

Userland is three different things with three different answers. The tools (gcc, pytest, node) are the workload — kept, but lent by the host. The plumbing (init, shell, coreutils, cron, dbus, ssh, package manager) is dumped entirely. libc is the compatibility contract — kept, statically linked, with no dynamic linker resolution at runtime.

What remains inside is pilot: a single supervisor that is PID 1 and the tool-call ABI at once. It replaces the shell by parsing shell syntax instead of executing it — POSIX sh text is compiled to a structured exec graph and run directly, so no /bin/sh process ever exists. The agent's trained-in bash fluency is preserved; metacharacters become syntax, not authority. Coreutils collapse into one static multicall toolplane binary written for machine callers: deterministic ordering, structured JSON on a dedicated fd, explicit exit taxonomies, no TTY detection, no color, no locale variance.

0x03The machinery

Three components. Two lanes. One fork.

forgectl
Fleet daemon · privileged · one per host

Owns the snapshot forest, the content-addressed store, manifests, and the shared page cache. The only component that touches the outside world. This is where "the distro" lives.

warden
Per-sandbox VMM · unprivileged · jailed

One process per agent, holding the KVM fds, vsock, and sealed page mappings. Can request pages from forgectl but reach nothing else — an escaped agent lands in a process that has nothing.

pilot
Cell supervisor · PID 1 inside the VM

The tool-call ABI, the shell parser, the taint tracker, and the toolplane binary. Baked into every snapshot, already running when the fork lands.

Control lane · vsocktool materialisation · egress requests · checkpoint / branch verbs · explain queries
Memory lane · sealed pagesattested tool pages mapped read+execute · shared host-wide · revoked by unmapping

The spawn flow — step through it

The lifecycle verb isn't boot. It's seal(intent) → cell, and it is literally a fork.

Exec-by-hash: the filesystem has no authority to run code

execve("/usr/bin/python") does not exist. Execution takes a content hash — exec(blake3:9f2c…) — and paths are a naming convenience resolved through a signed manifest. This inverts the supply-chain problem: instead of detecting bad code after it arrives, the cell is structurally incapable of running anything that wasn't attested at build time. A malicious postinstall script, a typosquatted package, a poisoned mirror — none can produce an executable page, because there is no code path for it.

Hypervisor-sealed pages: W^X below the guest kernel

Tool binaries live in host memory, mapped into cells via second-stage page tables as read+execute, never write — enforced by the hypervisor, not the guest kernel. This yields a property no current agent sandbox has: a full guest-kernel compromise still cannot modify tool code. An attacker owns ring 0 inside the VM and cannot patch curl or trojan python, because the pages are physically unwritable from the guest side. Free side effect: one physical copy of CPython serves ten thousand cells. Density and integrity are the same mechanism.

pip is a lie — and that's the point

Inside the cell, pip install requests works — as a shim RPC to the host. forgectl resolves the graph against its own mirrors, builds hermetically, scans and signs the artifact into the store, maps the pages into the running cell, and updates the manifest. The workload experiences a fast, normal install. What actually happened is a loan of attested memory. Verification happens once per artifact per fleet — the ten-thousandth cell to "install" numpy gets a page-table update measured in microseconds. Poisoning now requires compromising one hardened, auditable build pipeline instead of any cell's outbound TLS. The distro stops being a set of packages and becomes a lockfile with a build farm behind it.

0x04The trust model

Two lanes of provenance. Authority that only shrinks.

The live threat is rarely the toolchain — it's what the agent writes or fetches. So the kernel tracks one bit of provenance on every file: did this content come through the attestation gate, or was it created inside the cell?

TOOL LANE — born trusted

Manifest-attested binaries, hypervisor-sealed. Run with the cell's full — still small — authority.

DATA LANE — born here

Agent-written scripts, downloads, JIT output. Can execute — agents must run their own code; that's the job — but always under a per-execution Landlock/seccomp collar: workspace-only filesystem view, no control-lane access, no privileged verbs.

The laundering ban

Taint is inherited — a data-lane process's children and writes stay data-lane. And a tool-lane interpreter that takes tainted input to interpret is automatically demoted for that invocation: python evil.py runs as data-lane even though python itself is attested. This single rule closes the "use a trusted interpreter to escalate untrusted code" hole that every path- and binary-based allowlist shares.

The authority ratchet — click through the phases

A cell's rights are a ratchet, not a constant. Transitions fire on kernel-observable events and are enforced by warden on the host side — a fully compromised guest cannot reopen them.

Updates ship as lineage, never as mutation

There is no update mechanism inside the cell — that's the security model, not a gap. Patches ship as new snapshot roots; running sandboxes drain or live-fork onto the new lineage. Combined with exec-by-hash you get two speeds: instant kill for a bad hash — yank it from the manifest and it stops being executable everywhere, including in running cells — and generational rollout for everything else. Zero in-place mutation anywhere means an attacker looking for persistence has nowhere to write that survives dissolution.

0x05What it unlocks

Not a hardened sandbox. A different economics.

Density as a page-sharing problem

One physical copy of every tool serves the whole host. Per-cell cost is dirty pages plus a tmpfs workspace — an order of magnitude more concurrent cells per machine than image-per-sandbox designs.

Install time → fault time

Dependency materialisation becomes lazy page mapping from a warm snapshot forest. The 40-second npm install becomes microseconds for anything the fleet has seen before.

One supply-chain choke point

Every executable byte in every cell traces to one hermetic, signing build pipeline. Audit one pipeline, not ten thousand outbound TLS sessions. Fleet-wide revocation in microseconds.

Survives guest-kernel compromise

Hypervisor-sealed tool pages mean ring-0 in the VM still can't trojan a binary. The integrity guarantee doesn't depend on the guest being intact — a property nothing in the current field offers.

Fewer wasted turns

Deterministic output, structured errors, and self-explaining denials steer the model instead of confusing it. Teaching agents their constraints is already known to cut interruptions sharply — here it's built into the error surface itself.

Branching as an OS primitive

Checkpoint before every tool call; roll back on failure; fork three approaches in parallel — across process state, filesystem, and policy together. Exploration stops being expensive.

Injection with an expiry date

The authority ratchet means a prompt injection landing mid-task inherits a cell whose acquisition rights already expired. The attack window closes by construction, not by detection.

A distro that learns

The snapshot forest promotes hot tool-combinations observed in real trajectories into new warm nodes overnight. Package selection becomes a cache-placement problem with telemetry — the OS restructures itself around agent behaviour.

The defensible core

Nothing in the field today combines hypervisor-sealed tool pages, taint-lane demotion of interpreters, and fleet-learned snapshot topology. Those three, composed, are the novelty — everything else is disciplined assembly of proven parts.

0x06Risks & open decisions

What we're honest about.

Risk / decisionPosition
The build farm is the crown jewelConcentrating the supply chain creates one high-value target. Only a win if the pipeline is hermetic and reproducible from source — solved-but-expensive territory (Nix/Bazel class). This is where most engineering cost will live.
The JIT taxV8 and the JVM want writable-then-executable memory, which sealed pages forbid. JIT output runs as data-lane code; interpreter/baseline modes are an accepted perf cost inside a cell.
POSIX vs. intent-filteringWe keep the POSIX illusion — compatibility is a performance feature, because agents fail expensively. Research directions that replace the syscall ABI with intent declarations are watched, not adopted.
GPU scopeForces the hypervisor choice: VFIO passthrough gives near-native GPU access; user-space-kernel approaches block it. Decide before the VMM hardens.
Runtime misdetectionGo, the JVM, and Node size themselves from cgroups and /proc. With those cut, a synthetic /proc and /sys must lie correctly, or a 2-core cell thinks it's a 96-core host.
Where enforcement livesGuest enforces (fast), host verifies (trustworthy), mismatch dissolves the cell. Belt and braces, chosen deliberately.

How we validate the cuts: measure, don't guess

Before freezing the kernel config, run thousands of real agent trajectories under a logging seccomp filter and build the syscall-frequency histogram. Expected result: 99.9% of calls land in ~70 syscalls, the long tail comes from a handful of runtimes, and the surprises live in /proc reads rather than syscalls. That histogram is the kernel config — and it turns "we think this is safe to cut" into evidence.

The MVP path

warden — ~80% an existing microVM monitor, plus page sealing and the host-side ratchet.

pilot — the genuinely new code: shell parser, toolplane, taint tracking.

forgectl v0 — a hermetic builder, a signing key, and an mmap server; sophistication comes later.

Demonstrable end-to-end — seal from intent, lend a tool, demote a tainted exec, revoke a hash fleet-wide — with roughly three engineers in a quarter. The cell is open-sourceable without losing anything; the host pipeline is the moat.
