## Dispatcher preparation

`prepare_harness_fixture` prepares a new operator-owned state directory from
the signed package generated by `celln-harness-proof --package-only`. It stores
kernel/initrd/toolfs/runtime/closure by content hash, writes explicit publisher
and mote trust, and creates a model grant bound to
`sympozium:sympozium-system/harness-deployed-proof`. Its credential is only the
path `/etc/celln/model/token`; it neither reads nor copies token bytes.

Actual local preparation:

```sh
CARGO_TARGET_DIR=target/deployed cargo run -p celln-cli \
  --example prepare_harness_fixture -- /tmp/celln-harness-proof-40079 \
  target/deployed-kind.JcI9Gg/dispatcher-seed \
  sympozium:sympozium-system/harness-deployed-proof
```

The state was copied independently to each owned Kind worker's
`/var/lib/celln-deployed-proof`. The test-only StatefulSet fixture is committed
at `integrations/kubernetes/conformance/deployed-dispatchers.yaml`. It uses
required cross-node anti-affinity, one Service per dispatcher identity and an
ingress policy allowing only router Pods. It mounts `/dev/kvm` in privileged
Pods; this does not qualify the production host installer or a least-privilege
device-plugin deployment.

Dispatcher image `localhost/celln-dispatcher-proof:bb1e718` adds host-side curl
to the combined static CLI image. Config digest:
`sha256:12f5fe8d6e8afb0d2bfbf67e90bc6531161f4f73679f6a3e4554b357d7785389`.

Initial authenticated `/v1/node` correctly returned `guest_kernel:false`.
Current generic preflight requires `/boot` and matching `/lib/modules`, even
when a signed warm-mote bundle contains its kernel. Supplying the actual
`vmlinuz-7.1.13-200.fc44.x86_64` and matching modules read-only resolved that
prerequisite; no readiness check was bypassed. The rolling update exceeded the
45-second observation timeout but completed normally; neither state nor Pods
were force-recreated to work around that timeout.

Both dispatchers subsequently reported `kvm:true`, `cpu_virtualization:true`,
`guest_kernel:true`, accessible stores, zero live cells, and `warm:[]`.
Responses explicitly say `preflight_only:true` and
`availability_is_advisory:true`. Thus **no warm mote or executed cell is proven
by these responses**.
