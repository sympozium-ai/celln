REDESIGNED INTEGRATION · HERMITIC ACTIONS FIRST

Celln is a first-class execution choice for hermetic actions—not an Ensemble runtime.

Sympozium continues to own normal agents, AgentRuns, pipelines, delegation, shared memory, retries, and NATS/IPC. Celln is selected when a user or a parent agent needs one bounded, risky, or sensitive computation to execute in a sealed cell and return an immutable receipt.

Truthful availability: this is the approved product architecture, not a currently selectable backend. The Celln dispatcher still cannot launch a request. Until it returns a real receipt, the Sympozium control plane must show Celln as unavailable and must never fall back to a Job, gVisor, or Agent Sandbox while calling the action “Celln.”

Execution choice in the Sympozium UX

EXISTING

Standard AgentRun

Use for normal assistants, workflows, Ensembles, delegation, model credentials, shared memory, IPC, NATS, skills, and streaming results.

Backend: Kubernetes Job or Agent Sandbox.

PREFERRED FOR RISKY WORK

Celln hermetic action

Use for one immutable tool/program, declared inputs, named egress, bounded output, timeout, and hardware isolation.

Result: immutable output artifact plus Celln execution receipt.

NOT SUPPORTED

Celln Ensemble / AgentRun

Do not select Celln for an AgentRun that needs agent-runner, ipc-bridge, shared /ipc, NATS delegation, workflow memory, or token/result lifecycle.

Behavior: reject explicitly; never downgrade.

Control-plane ownership

Proposed API and relationship boundary

CellnAction
  spec:
    request: ExecutionRequest       # immutable mote/tool/input references
    parentAgentRunRef: optional     # ownership/correlation only; never authority
  status:
    phase: Pending | Running | Succeeded | Failed | Refused
    receipt: ExecutionReceipt       # terminal provenance

Ensemble relationship: celln-action
  source: persona / AgentRun
  target: CellnAction template
  handoff: immutable input artifacts only
  completion: validated receipt → bounded result card + immutable output reference
Forbidden: deriving a Celln executable from prompt text, image tags, ConfigMaps, paths, AgentRun.status.result, workflow memory, NATS records, or shared volumes. A Celln action that cannot be admitted or dispatched fails/refuses visibly; it is never executed by the normal AgentRun backend.

What must exist before the UX enables selection

  1. A real dispatcher resolves the requested content hashes, creates a Warden/microVM/sealed cell, executes the declared program, dissolves it, and returns a validated receipt.
  2. Sympozium has a dedicated CellnAction controller/backend with idempotency, cancellation, and receipt status—not an overloaded Job name.
  3. The action UI exposes actual node availability and refusal reasons. It defaults to Celln for eligible hermetic work only after live capability proof.
  4. The optional subordinate relationship consumes only an immutable output artifact and receipt; it does not pretend that Celln participates in delegation or shared memory.
