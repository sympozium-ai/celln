Getting started

From install to isolated work.

Celln drives an agent CLI you already trust—Codex, Claude, or Ollama. A KVM Linux host adds hardware-isolated cells for declared tools; generated programs use Celln's separate agent boundary.

Install

brew tap sympozium-ai/tap
brew install sympozium-ai/tap/celln

# Linux only: required to build static generated programs
rustup target add x86_64-unknown-linux-musl

Check what this host can support:

celln doctor

Connect an agent

celln setup     # discovers logged-in codex, claude, or ollama
celln agents    # shows available backends

celln setup saves your preferred backend. Change it later with celln agents --set-default anthropic, or override a single request with --agent.

Ask a question

celln ask "What does a binary tree look like? Explain it briefly."

celln ask uses your configured agent CLI directly. It is intentionally not a cell: no program runs and there is nothing to contain.

Build something

celln agent "Write a program that prints the first 100 primes, space separated."

celln agent shows the source with --show-source and runs generated code behind the agent boundary: no network and only a workspace filesystem. Use --allow-host example.com only when the task genuinely needs a named HTTPS host; Celln brokers that fetch rather than giving the guest a network stack.

Use a hardware-isolated cell

For a declared, verified tool workflow, generate a spec and run it on Linux with readable /dev/kvm:

celln spec init > agent.toml
celln spec check agent.toml
celln run agent.toml
celln verify

Read the boundary before treating a host as capable of hardware isolation. If KVM is unavailable, Celln says so; it does not pretend the fallback has the same property.
