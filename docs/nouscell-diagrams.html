NOUSCELL
/ NOWSS-cell / · a sealed cell of intelligence

Architecture reference. The distro lives on the host; the cell is an execution surface. Teal is host-lent, attested memory; amber is guest-born, collared data. Each panel is self-contained — screenshot any one into a deck.

host plane · trusted lent · attested (tool lane) born · collared (data lane)
01

The stack

What runs where. Everything above the KVM line is the trusted host; everything below is the presumed-hostile cell. The hardware boundary is the security boundary.
02

The machinery — three components, two lanes

forgectl and warden are host-side; pilot is inside the cell. Two channels cross the boundary: a control lane (requests) and a memory lane (sealed pages). Nothing else crosses.
03

Seal flow — task to first instruction

The lifecycle verb is seal(intent) → cell, and it is literally a copy-on-write fork. Authority derives from the signed manifest, never from the prompt.
04

Trust tiers — serve fast, upgrade async

Attestation is not the same as rebuilding. A cold request is served in seconds at Tier 2 while a hermetic Tier 1 rebuild runs in the background. Launch never waits on trust.
05

Two lanes of provenance · authority that only shrinks

Every file carries one bit: attested (tool lane) or born-here (data lane). An attested interpreter fed tainted input is demoted for that call. A cell's rights ratchet down and never reopen.
