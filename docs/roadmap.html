Execution-plane roadmap

Prove one request on one node before distributing it.

The execution-plane issues form a dependency chain. This is an ordering guide, not a release commitment.

First vertical slice: a signed request reaches one capable node, starts one sealed cell, and returns a versioned receipt or a truthful refusal.

Build the boundary first

  1. #1, define the execution request and result contract. It gives every later component one stable boundary.
  2. #3, project policy into capabilities. Authority must be default-deny before execution is admitted.
  3. #7, make brokers first-class capability providers. The first request needs bounded inputs, outputs, egress, and secret references.
  4. #6, serve signed dependency closures. A request can then name a runnable, immutable substrate.
  5. #13, dispatch one admitted request to a sealed cell. This proves the end-to-end execution and receipt.
  6. #2, prove the Sympozium-to-Celln reference path. Integrate only after the Celln path is truthful on its own.

What follows the first slice

Keep scheduling and node discovery as parallel design work, not prerequisites. Distributed revocation, provenance expansion, benchmarks, and conformance should validate a real execution surface after the first slice. The one-shot model needs proof before long-lived sessions become a dependency.

Celln is an open-source execution plane for agents. Source on GitHub.
