CELLN #13 · EXECUTION RUNTIME

From immutable request to one sealed cell.

The dispatcher is the missing execution boundary between Sympozium’s control plane and Celln’s Warden. It is a native Celln runtime—not a CRI shim, RuntimeClass, or Kubernetes Job fallback.

Current implementation state: the dispatcher now resolves a content-addressed MoteBundle, its kernel/initrd/toolfs objects, and the explicit requested program from integrity-checking stores. It does not yet launch that resolved bundle, harvest output, or publish a receipt. Those stages remain visibly marked below.

Runtime shape

What is implemented now

DONE
Explicit execution intent. ExecutionRequest.invocation selects one declared tool alias plus argv. It is validated against immutable tools[]; the tool list is not treated as an implicit command.
DONE
Resolvable mote-bundle contract. A MoteBundle is fetched from the hash named by request.mote. It binds the selected alias/program hash to immutable kernel, initrd, and toolfs hashes.
DONE
Integrity-checked resolution. celln node resolve REQUEST --mote-store … --tool-store … uses celln-store::Store::get for the bundle, program, kernel, initrd, and toolfs. A missing or corrupt blob is a refusal—not a host-path substitution.
DONE
Receipt contract. ExecutionReceipt binds request, cell/node identity, resolved authority, output hash, and terminal phase. It is not yet produced by a dispatcher.

Next executable slice

BUILDING
Native launcher. Materialize resolved kernel/initrd/toolfs only into dispatcher-controlled temporary files, construct LinuxCell, seal the exact toolfs pages, and run the in-guest Pilot. The first proof can cold-boot; the hot path must retain/fork a warm mote.
NEXT
Bounded output and receipt. Accept only Pilot terminal markers, cap stdout to outputBytes, place it in a content-addressed output store after dissolution, validate and serialize the receipt.
NEXT
Sympozium hermetic action. Present Celln as the preferred execution choice for eligible high-risk work, alongside gVisor/Agent Sandbox. It must use a dedicated CellnAction receipt API; it must not turn an AgentRun, its secrets, NATS, or shared memory into a fake Celln request.
INTENTIONALLY EXCLUDED
Full Ensemble backend. A Celln action is not an AgentRun executor. Ensembles retain the existing agent-runner, ipc-bridge, shared /ipc, NATS, workflow memory, delegation, retry, and token lifecycle. A future parent may await one immutable Celln-action receipt, but Celln does not participate in agent-to-agent workflow semantics.
