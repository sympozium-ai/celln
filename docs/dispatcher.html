CELLN #13 · EXECUTION RUNTIME

From immutable request to one sealed cell.

The dispatcher is the missing execution boundary between Sympozium’s control plane and Celln’s Warden. It is a native Celln runtime—not a CRI shim, RuntimeClass, or Kubernetes Job fallback.

Current implementation state: POST /v1/executions on a running dispatcher now validates a request, admits it against real node capacity, resolves the content-addressed MoteBundle and program, boots a real cell, and returns a genuine ExecutionReceipt — verified end-to-end on real KVM hardware. One gap remains, called out below rather than hidden: the guest still boots this host's own kernel, not the mote bundle's declared kernel/initrd hashes.

Runtime shape

What is implemented now

DONE
Explicit execution intent. ExecutionRequest.invocation selects one declared tool alias plus argv. It is validated against immutable tools[]; the tool list is not treated as an implicit command.
DONE
Resolvable mote-bundle contract. A MoteBundle is fetched from the hash named by request.mote. It binds the selected alias/program hash to immutable kernel, initrd, and toolfs hashes.
DONE
Integrity-checked resolution. celln node resolve REQUEST --mote-store … --tool-store … uses celln-store::Store::get for the bundle, program, kernel, initrd, and toolfs. A missing or corrupt blob is a refusal—not a host-path substitution.
DONE
Node admission. POST /v1/executions checks the request against this node's real, live-probed capacity (crate::node::admit) before anything is resolved or run — refused requests never reach a cell.
DONE
Native launcher. The exact program resolve_bundle verified is written into a fresh toolfs, admitted into this node's attested manifest, sealed read-only into a real LinuxCell, and run — no model asked to write the code, no forge step. Verified end-to-end on real KVM hardware.
DONE
Bounded output and receipt. Pilot's output markers are parsed, output is truncated to capabilities.outputBytes and content-addressed into an output store, and a validated ExecutionReceipt is recorded and served from GET /v1/executions/:id.

Known gap

PARTIAL
Kernel/initrd are verified, not booted. resolve_bundle proves the mote bundle's declared kernel/initrd hashes exist and match — but the cell still boots via BootConfig::host_kernel(), this node's own installed kernel, because DAX/nvdimm module loading checks kernel-module vermagic exactly against /lib/modules/<version> on the host. Booting an arbitrary stored kernel image would need its matching modules shipped alongside it, which the mote bundle contract does not carry yet. The sealed program is still the exact hash-verified bytes the request declared; only kernel provenance is a same-host assumption today.
PARTIAL
Router↔dispatcher traffic is plain HTTP. The bearer token that authenticates celln route → celln dispatcher (and a control plane → router) travels in cleartext, hand-rolled HTTP over TCP — no TLS. Fine on a trusted cluster network or localhost; not something to point across an untrusted network as-is. Adding TLS termination is unstarted work, not a hidden default.
DONE
Sympozium selects Celln for hermetic actions. AgentRun.spec.backend: celln dispatches to this runtime instead of a Kubernetes Job — see the architecture. Today that dispatch still goes through the older POST /v1/actions below, not the hash-pinned contract on this page; migrating the controller onto /v1/executions is the next concrete step, not a hypothetical one.
INTENTIONALLY EXCLUDED
Full Ensemble backend. A Celln action is not an AgentRun executor. Ensembles retain the existing agent-runner, ipc-bridge, shared /ipc, NATS, workflow memory, delegation, retry, and token lifecycle. A future parent may await one immutable Celln-action receipt, but Celln does not participate in agent-to-agent workflow semantics.

POST /v1/actions (a free-form {id, task, backend, model} submitted to an LLM, forged, and run) remains a separate, older endpoint on the same dispatcher — the prompt-driven path celln agent already used before this contract existed. It is not the hermetic path described here and does not produce an ExecutionReceipt.

Wire contract

ExecutionRequest.mote.hash ──▶ Store.get(bundle)
MoteBundle { kernel, initrd, toolfs, invocation { alias, toolHash } }
                             │
             Store.get(kernel/initrd/toolfs/program)
                             │
                   LinuxCell → Warden → Pilot
                             │
               bounded output Store.put(bytes)
                             │
                    validated ExecutionReceipt
