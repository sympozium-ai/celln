Sympozium × Celln is proven end-to-end on bare-metal Kubernetes.

A real AgentRun with backend: celln went through the full pipeline — Sympozium controller → Celln router → host-level dispatcher → DeepSeek API → forge build → assay verify → KVM cell execute — and returned "Hello from Framework Kubernetes".

ARCHITECTURE
KEY DECISION

The Celln dispatcher runs as a host-level systemd service, not a Pod. KVM persistent-memory mappings (KVM_MEM_READONLY) do not survive container layers — even with /dev/kvm passed through. Running on the host gives celln direct access to the hardware it audits.

The router stays in Kubernetes as a Pod (DNS discovery, scaling). The dispatcher runs once per KVM-capable node as a systemd unit.

# Celln installed as host binary $ /usr/local/bin/celln doctor kvm: true cpu-virt: true guest-kernel: true can_seal_cells: true # DeepSeek API key in environment $ echo $DEEPSEEK_API_KEY sk-***redacted*** # Dispatcher running as systemd service $ sudo systemctl status celln-dispatcher Active: active (running)

Create a Celln AgentRun:

cat <<EOF | kubectl apply -f - apiVersion: sympozium.ai/v1alpha1 kind: AgentRun metadata: name: celln-demo namespace: default spec: agentRef: demo agentId: primary sessionKey: demo backend: celln timeout: 300s task: |- write a Rust program that prints Hello from Celln and exits 0 model: provider: deepseek model: deepseek-chat authSecretRef: "" EOF
